🚀 Modul Praktikum: Git Revert

(Mode Hardcore: Anti Copy-Paste. Wajib Ketik Manual!)

📚 Materi & Konsep

Berbeda dengan git reset yang bersifat destruktif dan menghapus sejarah masa lalu, git revert adalah cara paling aman untuk membatalkan perubahan, terutama jika kode sudah telanjur di-push ke server.

Visualisasi Histori Revert

Inilah yang terjadi pada riwayat commit Anda saat menggunakan Git Revert. Masa lalu tidak dihapus, melainkan ditumpuk dengan commit pembatalan baru.

Membalikkan semua kode yang ada di Commit 2.
↑

Berisi kode yang menyebabkan error.
↑
🟢 Commit 1 Pesan: "Versi stabil awal"
Aplikasi berjalan lancar.

💻 Praktikum Step-by-Step

Langkah 1 dari 4

1. Membuat Skenario Bug

Mari kita simulasikan kondisi di mana kode kita sudah stabil, tapi tiba-tiba kita melakukan commit yang isinya bug (error).

Ketik perintah-perintah ini di terminal Git Bash Anda secara berurutan: 

mkdir latihan-revert 
cd latihan-revert 
git init 
echo "Versi 1: Aplikasi berjalan lancar" > index.html 
git add index.html 
git commit -m "Commit 1: Versi stabil awal" 
echo "Versi 2: Menambahkan fitur bug crash!" >> index.html 
git add index.html 
git commit -m "Commit 2: Yach.. aplikasi crash"
Kondisi Saat Ini:
Anda telah membuat sebuah file index.html. Di Commit ke-2, Anda tak sengaja menambahkan kode yang membuat aplikasi error. Anggap saja Commit 2 ini sudah telanjur di-push ke server.

2. Menyelamatkan Keadaan (Revert Terakhir)

Aplikasi crash di server! Anda harus cepat-cepat membatalkan Commit 2. Karena (diasumsikan) sudah di-push, jangan pakai git reset. Kita akan pakai git revert untuk membatalkan commit paling ujung (HEAD):

git revert HEAD
Tindakan yang Dibutuhkan:
Git akan membuka text editor default Anda (biasanya Vim atau Nano) untuk mengonfirmasi pesan commit pembatalan.
- Jika Vim: Ketik :wq lalu tekan Enter.
- Jika Nano: Tekan Ctrl+X, lalu Y, lalu Enter.

Sekarang, cek isi file Anda:

cat index.html

Tulisan "Bug crash!" sudah otomatis dihapus oleh Git!

3. Mengecek Riwayat (History)

Ini adalah bagian terpenting untuk memahami perbedaan mendasar antara Revert dan Reset. Mari kita lihat log commit Anda:

git log --oneline
Analisis Output:
Anda akan melihat ada 3 commit di layar. "Commit 2" yang error tadi TIDAK HILANG. Ia masih ada di sana. Tapi, ada commit ke-3 yang baru muncul (biasanya bernama "Revert: Commit 2"). Teman satu tim Anda yang melakukan pull tidak akan mengalami konflik riwayat.

4. Revert No-Commit (-n)

Kadang kita ingin membatalkan sesuatu, tapi mau mengedit filenya sedikit lagi sebelum benar-benar di-commit ulang. Kita akan pakai flag -n (no-commit).

Coba batalkan lagi hasil revert yang barusan:

git revert -n HEAD

Lihat status repositori sekarang:

git status
Hasilnya:
Perubahan pembatalan sudah masuk ke Staging Area, tapi belum menjadi sebuah commit. Anda bisa bebas memodifikasi file sekarang, dan jika sudah siap, lakukan git commit secara manual.

Selamat! Anda mahir menyelamatkan kode di Production! 🚀
