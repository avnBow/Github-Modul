Praktikum Interaktif: Git Revert

(Mode Hardcore: Anti Copy-Paste. Wajib Ketik Manual!)
1. Bikin Bug
2. Revert HEAD
3. Cek Histori
4. Revert No-Commit

Langkah 1: Membuat Skenario Bug

Mari kita simulasikan kondisi di mana kode kita sudah stabil, tapi tiba-tiba kita melakukan commit yang isinya *bug* (error).

Ketik perintah-perintah ini di terminal Git Bash Anda secara berurutan:

mkdir latihan-revert
cd latihan-revert
git init

echo "Versi 1: Aplikasi berjalan lancar" > index.html
git add index.html
git commit -m "Commit 1: Versi stabil awal"

echo "Versi 2: Menambahkan fitur bug crash!" >> index.html
git add index.html
git commit -m "Commit 2: Yach.. aplikasi crash"
Kondisi Saat Ini:
Anda telah membuat sebuah file index.html. Di Commit ke-2, Anda tak sengaja menambahkan kode yang membuat aplikasi error. Anggap saja Commit 2 ini sudah telanjur di-push ke server (walau sekarang kita cuma main di lokal).

Langkah 2: Menyelamatkan Keadaan (Revert Terakhir)

Aplikasi crash di server! Anda harus cepat-cepat membatalkan Commit 2. Karena (diasumsikan) sudah di-push, jangan pakai git reset. Kita akan pakai git revert.

Kita akan membatalkan commit paling ujung (terakhir) yaitu HEAD:

git revert HEAD
Apa yang terjadi setelah Anda menekan Enter?
Git akan langsung membuka text editor default Anda (biasanya Vim atau Nano). Git meminta Anda mengonfirmasi "pesan commit" baru.

Jika terbuka di Vim: Ketik :wq lalu tekan Enter untuk menyimpan dan keluar.
Jika terbuka di Nano: Tekan Ctrl+X, lalu Y, lalu Enter.

Sekarang, cek isi file Anda:

cat index.html

Tulisan "Bug crash!" sudah otomatis dihapus oleh Git!

Langkah 3: Mengecek Riwayat (History)

Ini adalah bagian terpenting untuk memahami perbedaan mendasar antara Revert dan Reset.

Mari kita lihat log commit Anda:

git log --oneline
Analisis Output:
Anda akan melihat ada 3 commit di layar. "Commit 2" yang error tadi TIDAK HILANG. Ia masih ada di sana. Tapi, ada commit ke-3 yang baru muncul (biasanya bernama "Revert: Commit 2").

Inilah kenapa Git Revert sangat aman: Ia tidak menghapus sejarah masa lalu, melainkan menumpuk masa lalu dengan commit pembatalan baru. Teman satu tim Anda yang melakukan pull tidak akan bentrok riwayatnya.

Langkah 4: Revert tapi Jangan Langsung Commit

Kadang kita ingin membatalkan sesuatu, tapi kita mau mengedit filenya sedikit lagi sebelum benar-benar di-commit ulang.

Kita akan pakai flag -n (no-commit). Coba jalankan ini (kita batalkan lagi hasil revert yang barusan):

git revert -n HEAD

Lihat status repositori sekarang:

git status
Hasilnya:
Perubahan pembatalan sudah masuk ke Staging Area, tapi belum menjadi sebuah commit. Anda bisa bebas memodifikasi file index.html sekarang. Jika sudah siap, Anda harus melakukan commit manual dengan perintah git commit.

Selamat! Anda sudah mahir menyelamatkan kode di Production! 🚀
